# Инструменты: текущая реализация

Инструменты находятся в `tools/`, исторические скрипты `.doc/scripts/` сохранены. Статические проверки переосмысляют HTMLParser-проверку старого `check_vanilla.py`; браузерная пара и заморозка анимаций основаны на подходе `render_util.py`, без селекторов клуба. Это начальный универсальный комплект, не полная реализация плана.

## Установка

Статические команды требуют Python 3.9+ (тестировались на 3.11). Для сравнения нужны Playwright, Pillow и Chromium:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements.txt
.venv/bin/python -m playwright install chromium
```

Для автоматического запуска `source/` дополнительно необходимы Node.js и npm или pnpm совместимой с экспортом версии; для pnpm может использоваться `npx` с точной версией из `packageManager` или `.mise.toml`. Для Windows использовать `.venv\Scripts\python.exe`. В некоторых средах скачивание Chromium заблокировано или нужны системные библиотеки. Если в текущей Linux-среде уже подготовлен локальный Chromium в `.cache/browser-runtime/`, перед запуском можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE="$PWD/.cache/browser-runtime/chromium"` и добавить `$PWD/.cache/browser-runtime/lib` в `LD_LIBRARY_PATH`. Кэш не версионируется и может отсутствовать после перезапуска среды. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` на совместимый установленный Chromium; версии могут отличаться визуально. `browser-audit --trust-source` может устанавливать зависимости и исполнять экспорт, но не изолирует его на уровне ОС.

## Поэкранная сверка для агента

Для обычной проверки достаточно одного браузера — Chromium: эталон и результат проверяются в одинаковом движке и окружении. Установка или проверка других браузеров не требуется без отдельного запроса.

На запрос «сверь в браузере вёрстку» применять [навык browser-parity](../.agents/skills/browser-parity/SKILL.md). После анализа кода и оценки безопасности: `.venv/bin/python -m tools.cli browser-audit --trust-source`. Для стандартного Vite с npm/pnpm lock команда сама запускает копию `source/` и `vanilla/`, фиксирует мобильный 390×844, планшет 768×1024 и десктоп 1440×900, снимает каждый экран отдельно и останавливает процессы. Можно передать `--reference-url` и `--candidate-url` вместо запуска, `--route`, `--scenario`, `--font-css`, `--threshold`, `--channel-tolerance`, `--output` и `--json` (см. `--help` и навык). Для каждого экрана, длинной страницы и снимка сразу после действий сохраняются исходник (`reference`), результат (`candidate`), сырой `diff`, `overlay` и `heatmap`. `brief.json` содержит до 8 наиболее заметных записей и до 8 уникальных предупреждений; `summary.json` — полные метрики, состояния и предупреждения. Обычный вывод также ограничен, `--json` печатает всё. Начинайте с краткого отчёта и только нужных изображений.

### Как читать изображения

- `overlay`: каждый пиксель — 50% эталона и 50% результата; двойные края показывают сдвиг. `diff`: абсолютная разница RGB, мелкие отличия могут быть тёмными. `heatmap`: поверх результата красным отмечены пиксели, где хотя бы один канал отличается **более** `--channel-tolerance` (по умолчанию 12 из 255). Непарная область разной ширины или высоты отмечена пурпурным и всегда считается отличием, даже при tolerance 255. Снимки не обрезаются: холст берёт максимумы ширины и высоты, размеры указаны в JSON. `difference_ratio` — доля отмеченных пикселей; `any_difference_ratio` — доля любых отличий; `--threshold` (по умолчанию 0.001) — допустимая доля, не порог RGB. Для строгой проверки: `--channel-tolerance 0 --threshold 0`.
- `full-*` — Playwright full-page после возврата к началу, а не сшивка экранов; `001-*` и далее — фактические viewport при прокрутке, `action-*` — viewport сразу после сценария до подготовительной прокрутки. Из-за sticky/fixed, lazy-load, состояния прокрутки, разных высот и асинхронного контента они могут различаться. Смотрите `actual_y` и `offsets_match`: браузер ограничивает прокрутку у короткой страницы, поэтому экранные снимки могут иметь разные offsets. Различие высоты фиксируется отдельно. Full-page — дополнительная диагностика и само по себе не меняет статус экрана/состояния.
- Ограничение full-page — 12 млн пикселей общего холста; при превышении или ошибке длинный снимок не сохраняется и выводится предупреждение, поэкранные снимки остаются (до 100 экранов на состояние). Иные ошибки конкретного состояния помечают его `BLOCKED`. Динамический контент может измениться после подготовительной прокрутки. Скриншоты и сценарии могут содержать чувствительные данные: используйте только тестовые и не публикуйте артефакты без разрешения.

`--trust-source` разрешает запуск исполняемого кода и загрузку зависимостей; временная копия, запрет lifecycle scripts и урезанный environment **не обеспечивают изоляцию ОС**. В случае недоверенного экспорта применять полноценную песочницу. Не отправлять реальные формы. Без сценариев проверено только начальное состояние; пользовательские правки и повторные прогоны выполняет агент. Шрифты и недостающие файлы влияют на достоверность: пиксельные различия при предупреждениях состояния помечаются `REVIEW`, предупреждения сами по себе не блокируют проверку; отличия текста, контролов и высоты сообщаются отдельно и могут дать `FAIL`. Один прогон не выдаёт полную приёмку (`INCOMPLETE`).

Сравнение видимого текста сообщает факт расхождения; отчёт также содержит сведения о части видимых элементов управления. **Сопоставление отдельных DOM-элементов, их координат и вычисленных CSS-стилей между React и vanilla пока не реализовано.** Прочитать причины расхождений в CSS/DOM может агент вручную, а изображения остаются дополнительным свидетельством. Сценарии взаимодействий не выбираются автоматически и не доказывают полноту проверки поведения.

## Команды

Из корня репозитория:

```bash
python -m tools.cli analyze --source source --json
python -m tools.cli check --site .work/staging/example --json
python -m tools.cli compare --reference http://127.0.0.1:8084/ --candidate http://127.0.0.1:8081/ --width 390 --height 844 --output .work/compare/mobile --report .work/reports/mobile.json
python -m unittest discover -s tests -v
```

`analyze` не исполняет код; определяет один `package.json`, lock-файлы, некоторые зависимости, LFS-указатели, symlink и некоторые отсутствующие буквальные `src` в исходниках. Многое, например вычисляемые пути, может не обнаруживаться. `check` обходит HTML и CSS, проверяет некоторые базовые теги, ссылки, повторные id, alt, LFS и синтаксис используемых SVG; поддерживает также отложенные ресурсы `data-image-src`; отсутствующие файлы и LFS-указатели попадают в `warnings`, а не в `issues` и не приводят к FAIL/BLOCKED. Абсолютные пути также выдаются как предупреждение. Это **не HTML5-валидатор**, не полноценный CSS-парсер и не проверка корректности изображений. Внешние ссылки и JavaScript-пути статически не проверяются.

`compare` открывает только локальные HTTP URL с портом. Запросы вне текущего origin и методы кроме GET/HEAD блокируются и фиксируются; JavaScript страниц выполняется, поэтому запускать проверку и серверы следует только в изолированной среде без чувствительных сервисов. Блокировка сети не является безопасной песочницей, GET тоже может менять данные. Не открывайте недоверенный эталон рядом с важными локальными сервисами. Сравниваются текст, количества ряда элементов, размеры, полный снимок страницы и пиксели (порог разницы каналов 12; доля допустимых различий `--threshold`, по умолчанию 0.01). Размеры изображений не обрезаются. Недоступные подресурсы, включая HTTP ≥400 и ненагруженные изображения/внешние шрифты, дают предупреждения. Навигация к недоступной странице и ошибки, из-за которых проверку нельзя выполнить, остаются BLOCKED. При предупреждениях о ресурсах различия размеров и пикселей также отмечаются как ненадёжные предупреждения; несоответствие текста и количества элементов по-прежнему показывается как FAIL. Нет гарантии проверки всех font-face, состояний, маршрутов и сетевых ошибок. При необходимости сохраняйте отдельные снимки для каждого viewport/сценария.

Для простого интерактивного состояния передайте `--scenario path.json`, где JSON — массив, например:

```json
[{"type":"click","selector":"button[aria-label='Открыть меню']"},{"type":"press","key":"Escape"}]
```

Поддержаны клики по единственной кнопке (кнопка отправки внутри формы запрещена), Tab/Escape и `{"type":"scroll","y":300}`. Действия применяются одинаково к обеим страницам. Не запускайте сценарии, если кнопки выполняют опасный код: сам факт того, что это кнопка, не делает действие безопасным. Иные интеракции нужно проверять вручную. Снимки записываются только в новый/пустой подкаталог `.work/`, отчёты — в новый файл `.work/`; существующие отчёты не перезаписываются.

Статусы и exit-коды: `FAIL` = 1, `INCOMPLETE` = 2, `BLOCKED` = 3. В текущей версии ни одна отдельная команда не присваивает итоговый `PASS`: результаты отдельных проверок недостаточны для приёмки. JSON содержит версию схемы, ошибки, `warnings` и дальнейшие действия; в текстовом выводе предупреждения показаны с префиксом WARN. Предупреждения о файлах не меняют статус и exit-код относительно того же прогона без них (отдельные команды всё равно дают INCOMPLETE, поскольку это не полная приёмка).

Браузерные интеграционные тесты дополнительно запускаются с `RUN_BROWSER_TESTS=1` после установки Chromium. Синтетические данные тестов временные, файлов клиента не содержат. Автоматический выбор всех сценариев, полнофункциональный HTML5-валидатор, защита публикации и генерация ванильного сайта пока не реализованы; см. план.
