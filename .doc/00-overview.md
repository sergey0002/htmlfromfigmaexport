# Конвертация Figma Make (React / Vue) → чистый SEO-HTML — обзор

## Цель

Из исходника Figma Make (React + Vite + Tailwind или Vue + Vite) получить
папку статического сайта без фреймворков — **только готовый сайт, ничего лишнего**:

```text
vanilla/                  ← чистая поставка (БЕЗ генераторов и служебного)
  index.html              — готовый SEO-размеченный документ
  css/style.css           — весь дизайн, без Tailwind в рантайме
  js/app.js               — поведение 1:1 (скролл, меню, табы, подсветка)
  img/                    — все растровые ассеты из src/imports
  favicon.svg / -16 / -32 / apple-touch-icon / og-cover
```

Служебное живёт в `.doc/` (не поставляется): шаблон-генератор, скрипты, доки.

Эталон данного проекта — сайт «ФБК Таргет»:
React-вход `src/main.tsx` → `src/App.tsx` (904 строки), стили `src/index.css`,
ассеты `src/imports/` (17 файлов), сборка `hosting/` (Vite), ванилла `vanilla/`.

## Скрипты (`.doc/scripts/`, Python 3.8+, без зависимостей)

```powershell
python .doc/scripts/analyze_figma_export.py . --write   # отчёт по новому исходнику
python .doc/scripts/make_seo_pack.py --url https://site.ru/ --name "…" [--logo …]
python .doc/scripts/check_vanilla.py vanilla --url https://site.ru/   # 0 FAIL = готово
```

Шаблон генератора: `.doc/templates/build.mjs` (копировать в рабочий каталог
проекта, а не в vanilla; после регенерации в vanilla остаётся только сайт).

## Принципы (обязательные)

1. **Единственный h1** на страницу, иерархия `h1 → h2 → h3` без пропусков.
2. **Данные — в шаблоне-генераторе** (`.doc/templates/build.mjs`), `index.html`
   всегда сгенерирован; в `vanilla/` — только готовые файлы.
3. **Никакого React/Vue в рантайме** финального сайта: один `style.css`, один `app.js` с `defer`.
4. **Pixel-parity**: брейкпоинты, отступы, шрифты (Oswald + Inter), цвета — 1:1.
5. **Относительные пути** (`./css/style.css`, `./img/x.png`) — сайт обязан открываться
   из любой подпапки и после заливки содержимого в корень хостинга.
6. **On-page SEO обязателен** (head, OG/Twitter, JSON-LD, фавиконы — см. `05`).
   Серверные файлы (robots.txt, sitemap.xml, PWA-манифест) — только по явной
   просьбе; в поставку по умолчанию не входят, не выдумывать файлов, которых
   не было в макете (PDF-документы и соцсети — контент заказчика).
7. **Ноль инлайн-стилей**: в HTML ни одного `style=` — весь дизайн через классы
   `style.css` (см. `02 §2.4`); валидатор ставит FAIL за каждый найденный.
8. **Чистый CSS**: слои 1→10 с русскими комментариями, ноль мёртвых классов,
   одинаковые виды слиты в групповые селекторы (см. `03 §3.6`); валидатор
   предупреждает о мёртвых классах.

## Быстрый цикл работ с новым исходником

```text
1. python .doc/scripts/analyze_figma_export.py <корень> --write   → отчёт (01).
2. Скопировать img → vanilla/img, зафиксировать размеры фото (03 §3.4).
3. Шаблон .doc/templates/build.mjs → рабочий генератор → node build.mjs (02).
4. Написать style.css (03) → сверить 390 / 768 / 1024 / 1440.
5. Написать app.js (04) → сверить меню, табы, скролл, hover.
6. python .doc/scripts/make_seo_pack.py … (05) + head в шаблон.
7. python .doc/scripts/check_vanilla.py vanilla --url … → 0 FAIL; в vanilla —
   только готовый сайт (убрать генератор и служебное).
```

## Что считать «готово»

- `check_vanilla.py` → **0 FAIL**; WARN только с объяснением (PDF/соцсети заказчика).
- В `vanilla/` нет ничего, кроме готового сайта (06 §6.1).
- Сетки на 390/768/1024/1440 совпадают с оригиналом, горизонтального скролла нет
  (кроме разрешённого `.table-scroll` для широкой матрицы).
- Фото игроков видны целиком (лица, не «макушки»), см. `03-css-responsive.md §3.4`.
- Любая строка таблиц подсвечивается золотым при наведении, Таргет выделен всегда.
- Мобильное меню открывается с fade + stagger-подъёмом пунктов, закрывается по
  пункту, кресту и `Escape`.
- Lighthouse: Performance ≥ 90, Accessibility = 100, Best Practices = 100, SEO = 100.
