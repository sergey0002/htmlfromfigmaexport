# Точечные правки и поведение

1. Уточни ожидаемый результат по запросу и коду; проверь `git status`, сохрани пользовательские изменения. Выяви маршрут, размеры, элементы и состояния, где проблема проявляется. Для сверки с исходником используй `source/` только как недоверенный эталон, не исполняй без оценки и изоляции.
2. Если пользователь просит новое поведение или изменение дизайна, реализуй это как новое требование даже при отсутствии в React. Отличай его от регрессии; не откатывай запрос ради пиксельного совпадения и не придумывай несуществующий backend. Для неоднозначных важных требований уточни у пользователя.
3. Воспроизведи проблему в безопасном браузере, если возможно; исправь причину минимальными правками HTML/CSS/JS. Проверь целевой сценарий, закрытие/обратное действие, клавиатуру, доступность, затронутые маршруты, соседние компоненты и релевантные мобильный/планшет/десктоп.
4. Для неизменённых частей при наличии эталона используй `../browser-parity/SKILL.md`; оцени расхождения с учётом намеренного изменения, не скрывай их. Новую функциональность проверяй по запросу, а не по отсутствующему примеру. Никаких реальных отправок форм, платежей и изменения данных без явного разрешения и изоляции.
5. Сначала читай компактный `brief.json` и только нужные heatmap/overlay и фрагменты `summary.json`, не выгружай в контекст все снимки. Повтори после исправления; сообщи что проверено, что намеренно отличается и что не удалось проверить. Недостающие ресурсы — предупреждения, а не самостоятельный блокер.
